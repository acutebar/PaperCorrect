\section{Introduction}
The core aim of this project is to reconstruct a 3D surface from a single picture using information from geodesics on the surface. In particular, the focus is on reconstructing surfaces formed by ruled papers.
In this case, the geodesics we use to extract information about 3D embedding are the rulings.\\~\\
For example, consider a horizontally ruled paper that is curled in a cylindrical way along the vertical axis and away from the camera. Assume also that the camera is placed at a height above the paper along its center. 
A picture will depict a straight horizontal line at the center with horizontal lines on either side of the middle line appearing increasingly curved towards the central line (see image below).
\begin{figure}[h]
  \centering
  \includegraphics[width=0.3\textwidth]{example_curve.png}
  \label{fig:example_curve}
\end{figure}
The goal is then to use this information about how the lines curve to recover the paper's original 3D embedding. Our method is as follows: we 
compute the curvature of each ruling using the geometric form it assumes in the original picture. We integrate the square of the curvature along each geodesic and sum them to obtain the \emph{geodesic energy} of the
flat image. We then
deform the flat surface of the image in various ways (in three dimensions), compute the energy after these deformations, 
and find the deformation of the surface that provides us with the minimum energy possible (using gradient descent).
Theoretically, if the deformed surface matches the original 3D embedding, the energy must be exactly zero. \\~\\
We provide a detailed explanation of the implementation and the method in the following sections. We begin by briefly explaining the method used to detect edges and clean up the image to isolate dark lines and detail
the method used to detect and trace continuous curves on the image so as to recover a dense cluster of points that will be treated as a single curve. The next section will explain how the cluster of points is converted
to an analytic curve whose derivatives (and hence curvature) are easy to compute. This method also generalizes to fitting surfaces to a cluster of points in three dimensions (which will be used later). Following this, 
we proceed to mathematically explain the algorithm along with its implementation that allows us to compute the geodesic energy for any deformation of the original picture. We then explain the gradient descent used
to minimize energy and explain why the algorithm is necessary. Finally we list some limitations of the current implementation along with methods to improve results.

\section{Tracing Curves}
This section will focus on detecting edges and isolating and tracing continuous curves from start to end. First, we briefly explain how a raw grayscale image is converted to black and white with all detected edges colored black
and the rest of the background white. This is called adaptive thresholding. \\~\\
The idea behind adaptive thresholding is simple: we iterate through all pixels in our original image (which is in grayscale). At each pixel, we compare the value of the pixel with the mean of its surroundings (for example, 
take a neighborhood of the pixel formed by a 30 pixel circle around it). If the value falls below the mean minus the standard deviation, we color the pixel black. If not, the pixel remains white. This method can be found in
\verb|detector/edge_detector.py|. \\~\\
This method is noisy so it can be improved by first passing the grayscale image through a Gaussian blur filter. This acts as a low pass filter and removes noise. In particular, the transformation is given by the following equation:
\[
  P_{\text{blur}}(x_0, y_0) = \sum_{(x, y) \in U}K(x-x_0, y-y_0) P(x, y)
\]
Here, $U$ is a small neighborhood of $(x_0, y_0)$, $P$ is the pixel value of the original image and $P_{\text{blur}}$ is the pixel value of the filtered image. Note also that $K$ denotes the Gaussian Kernel, which is simply 
a normalized Gaussian distribution chosen appropriately for a given size of the neighborhood $U$. Note that it suffices to choose a square or circle of fixed dimension around the origin and shift it appropriately to obtain $U$. \\~\\
The method is further improved if instead of taking the naive mean of pixels in the neighborhood, we take a weighted mean, where the weights are provided by the Gaussian Kernel. Often, the threshold for declaring a pixel
to be black is a fixed number rather than based on standard deviation. For the rest of our project, we use Gaussian blur followed by OpenCV's adaptive thresholding module, which follows an implementation conceptually identical
to the latter method. This is called directly in \verb|test_gd.py|. \\~\\
Performing the above steps provides us with a clean image where the rulings are reliably blackened and noise reduced. See Figure \ref{fig:thresholding_pipeline} for results.

We thus move on to the harder problem of tracing each ruling from start
to end. Here, given an input image, we would like to output a list of ``lines'' where each line is described by a list of coordinates. This allows us to work with each ruling (geodesic) in isolation for the rest of the project. \\~\\
Conceptually, the algorithm used to execute this task is as follows: We iterate through each point $p$ in the image, and if we detect a dark pixel, 
we fix a $1\times n$ rectangle $Q$ (in practice, $2\times 5$ works well) with one corner fixed at $p$.
This will resemble our velocity vector. We compute
the mean pixel value of this rectangle. Following this, we rotate $Q$ by a small angle (for example $5$ degrees) repeatedly and measure the mean pixel value each time. We declare the minimum of all these pixel values is
the direction in which the curve continues, provided that this value is below a fixed threshold. We then let $p$ be the new point that the vector $Q$ points to and continue the process until we see no new points 
that are below the threshold. \\~\\
In practice, executing this algorithm naively will result in the program detecting multiple broken curves along each large curve. This issue persists even if we maintain a global \verb|visited| list, and as we
traverse our curve, add every point between the old pivot and the new point, along the vector, to the list (this is also required to prevent the program from getting stuck in a loop during traversal). \\~\\
However, this does not suffice since our iteration might hit a midpoint of a curve well before it hits any end points, leading to the program attempting to trace a curve starting from a midpoint. This will give rise to broken
curves. To fix this, we must add conditions to ensure that the algorithm never starts at a 
midpoint and a \verb|sweep| variable is introduced to this end. At each point, instead of finding a single, global minimum, we find a few local minimums over various sections of the circle formed by the \verb|sweep| angle.
So rather than immediately iterating $\theta$ from $0$ to $360$, we first iterate it from $0$ to $\phi$ and find a minimum (if it meets the threshold requirement). We then find yet another minimum in the next sweep 
of $\phi$ degrees, if it exists, and so on. Now, if we do detect more than one local minimum at the very beginning of the curve tracing, the program must not proceed since this is likely a midpoint of 
some curve starting elsewhere. This effectively ensures that curves remain unbroken in the case of non-intersecting curves. \\

In the actual implementation, the mean was computed every $5$ degrees and added to a list (along with the angle at which this occurred and so on). Evaluating the local minimum was then done using a sliding window 
(which wraps around) of size $\phi/\theta$ on either side each entry to determine whether it is a local minimum of that window.

The above approach is highly effective for most curves that are not closed and do not intersect other curves. However, for the purposes of this project, we will need to add an extra condition
that cuts a curve off if it develops sharp turns. This is important to ensure that background noise near and outside the edge of the paper that appears like a sharply bent curve is not considered in our
energy computation (we only want geodesics). Further, if a paper has text or scribbles, we do not want these marks to be detected as rulings.

\section{Fitting Curves using Splines}\label{sec.fit}
Until now, we have processed the image significantly. We have cleaned up the paper and detected curves individually, as distinct collections of points. But we need to work with the acceleration of a curve, 
and we would like to find the acceleration at any given point. One approach could be to simply subtract adjacent velocity vectors that are stored simply as straight lines joining a point to the next. This is however a very
crude approximation and does not give us the acceleration at all points. \\~\\
To solve this, we fit curves. For simplicity, we will assume that the curve can be described by a function. So the goal is to accurately fit a function $f$ to a dense enough collection of points $[(x_i, y_i)]$.
Fitting a global function to the entire curve using the least squares approach is impractical since this approach is prone to under fitting and overfitting. But the fit will remain acceptable if we only work in a small
subset of the full collection of points.
We can repeat this over multiple small neighborhoods. It is then natural to use partitions of unity to tie these local fit functions into a global function. \\~\\
To be precise, we will split the domain into overlapping segments, which we will call $U_i$. We may then restrict our dataset to $\{(x_j, y_j)\}_{x_j \in U}$ and fit a function $f_i$ to these points. We repeat this over
all values of $i$. Then, we find a collection of smooth functions $\rho_i$ that are supported in $U_i$, i.e. $\rho_i(x) = 0$ for all $x \notin U_i$. We additionally ensure that $\sum_{i} \rho_i = 1$ everywhere. The collection
of functions $(U_i, \rho_i)$ is called a partition of unity subordinate to the {cover} $U_i$ of the domain. Our global function is then $f(x) = \sum \rho_i(x) f_i(x)$. Since each $f_i$ is a local fit, $f(x)$ will resemble 
the global function and moreover $f$ is guaranteed to be smooth. Note that it suffices to use quadratic functions $f_i$ to fit each local collection of points. \\~\\
The only issue with this approach is that in order to compute $f'(x)$ and $f''(x)$ (which are needed for the curvature), we will need to know the derivatives of $\rho_i(x)$. Once we know this, the computation is easy
using the chain rule. If we require $\rho_i$ to be smooth
in the sense of $C^\infty$, this is unfeasible. However, we can construct partitions of unity such that $\rho_i \in C^k$ while ensuring that the first $k$ derivatives are easy to compute. This is detailed
\href{https://personal.math.vt.edu/embree/math5466/lecture10.pdf}{here}. \\~\\
This works if the dataset $\{(x_i, y_i)\}$ represents a function $y = f(x)$. However, this is not always the case, since we may have vertical rulings instead of horizontal rulings. To this end, we construct a time domain
$T = \{t_i\}$ so that the curve is described by the dataset $\{t_i, x_i, y_i\}$. We may then separately fit two functions $x(t)$ and $y(t)$ to obtain the full parametrization of the curve $\gamma$ in consideration. 
We also need to take care in choosing our time domain appropriately to ensure that two time intervals of equal elapsed time have approximately the same number of points. If not, we will have bad fits in some 
intervals and good fits in other intervals. However, we indeed have this for free from our method of tracing curves. We used a fixed length vector to find successive points on the curve so consecutive points
are equidistant in the plane. It therefore suffices to use total arclength to parametrize our dataset.
This method thus naturally produces $x(t), y(t)$ along with the first two time derivatives of each function. The curvature is then simply $(x''(t), y''(t))$. Even though we do not have a single closed form representation
for the entire curve, we can compute $x(t)$ and $y(t)$ and their derivatives at any given point in time $t$. \\~\\
\begin{figure}[htpb]
  \centering
  \includegraphics[width=0.5\textwidth]{curve_fit.png}
 \caption{Continuous curve reconstruction via partitions of unity.}
  \label{fig:curve_fit}
\end{figure}

Furthermore, this approach generalizes naturally to two dimensions (and even more). If we have a cloud of points $\{(x_i, y_i, z_i)\}$, we divide the domain into overlapping neighborhoods $U_i$ (rectangular neighborhoods 
for instance), fit the curve using a least squares polynomial fit locally in this neighborhood, and finally use a partition of unity $\rho_i$ subordinate $U_i$ to evaluate the global function (and its derivatives if required)
at any given point. The approach described in Embree also works in two dimensions. The functions $\rho$ are easy to construct from the functions $\rho_i$ in one dimension. In particular, if $\rho_j$ corresponds to 
the 1D bump function supported in $I_j$, then we can simply let $U_{jk} = I_j \times I_k$ and let $\rho_{jk} = \rho_j(x)\rho_k(y)$. \\~\\
In this project, we have used a slightly crude modification of the approach explained above. Rather than beginning with overlapping neighborhoods $U_i$ and fitting functions $f_i$ over all of $U_i$, we
partition the domain into disjoint intervals of a fixed \verb|bin_size|. Denote these disjoint partitions by $P_i$ and we ensure that $P_i \subset U_i$. Now, we fit a function $f_i$ over the domain $P_i$ instead of $U_i$
and crudely assume that this provides a valid fit over all of $U_i$. This gives us the required collection of functions $f_i$ along with the partitions $\rho_i$. \\~\\
See Figure \ref{fig:curve_fit} for a result of the curve fit. In order to interactively view the fit curve with velocity and acceleration vectors displayed pointwise, run \verb|interface.py|. You will be asked
to crop a region to work with, after which you must click on a curve and hover at a point to on the curve to view the vectors at that point.

\section{The Core Algorithm}
In this section we set up and resolve the central part of the problem. First, we understand the scope of the information that taking a picture of a curved piece of paper gives us. \\~\\
Let $S \subset \R^3$ be the surface that we are taking a picture of and suppose the camera is positioned at $0 \in \R^3$. The camera also has a physical screen given by the flat plane $P = \{(x, y, f) \colon x, y \in \R\}$
(we assume $S$ lies in the other half space). Here $f$ is the focal length and all images are formed on $P$. The picture $Q$ captured is thus a subset $Q \subset P$ where each point in $Q$
uniquely corresponds to exactly one point in $S$ (assuming we can see every point in $S$) via scaling. The correspondence also preserves information, i.e. the pixel value at $(x, y, f) \in Q$ exactly equals the light intensity
at $\lambda(x, y, f) \in S$ where $\lambda$ is the required scaling factor. \\~\\
So we now have a subset $Q$ of points of the form $(x, y, f)$ and we want to find some way to deform $Q$ so that we recover $S$. We must be careful to ensure that the deformation continues to preserve the correspondence 
derived from scaling. More precisely, we can state it as follows: we want to find a function $\phi \from Q \to \R^3$ with the constraint $x \in Q \mapsto \lambda_x x$ for some $\lambda_x\neq 0 \in \R$, such that
$\phi(Q) = S$. A simpler formulation is thus: we want to find $\rho \from Q \to \R$ such that $S_\rho \defeq \{\rho(x) x \colon x \in Q\} = S$. \\~\\
While the above formulation is mathematically precise, it does not make our work easier since we still do not know anything about $S$. This is where the rulings come in. In 3D space, $S$ is a surface and the rulings are geodesics 
on $S$. But when we take a picture of $S$, the curves are pointwise transferred to the image $Q$, but these are no longer geodesics on the surface $Q$. To be precise, suppose $\eta$ is a geodesic on $S$ which is parametrized
by $\eta(t) \from [0, 1] \to S$. For simplicity, we assume that $\eta$ has a constant speed of $1$ 
(in practice we will have to abandon this assumption to make computations work out) and until explicitly stated, we assume that all curves
have constant speed $1$.
The curve $\eta$ has no acceleration outside of the surface's own bending (this is the definition of a geodesic). Thus,
\[
  \int_0^T \abs{[\ddot \eta(t)]^T}^2 dt = 0
\]
On the other hand, if $\gamma(t)$ is the corresponding curve in $Q$, the same integral for $\gamma$ is absolutely not $0$ (we are still assuming that $\gamma$ has constant speed). Here $\ddot \gamma(t)^T$ denotes the projection of the vector $X$ onto the tangent space at the point 
$\gamma(t)$. The method is thus clear: we will search for $\rho \from Q \to \R$ with the aim of obtaining
\[
  E_\gamma[\rho] = \int_0^{T_\rho} \abs{[\ddot \gamma_\rho(t)]^t}^2 dt = \int_0^{T_\rho} \abs{\left[\frac{d^2}{dt^2}(\rho(\gamma(t))\gamma(t))\right]^T}^2 dt = 0
\]
Here we use $\rho(\gamma(t)) \gamma(t)$ since this is the exact form of the new curve corresponding to $\gamma$ on the deformed surface $S_\rho$. There could be multiple surfaces different from $S$ that lead to 
$E_\gamma[\rho] = 0$, but if we do the same with multiple different $\gamma$, we get closer to the true surface. One may point out that four edges of a rectangular piece of paper suffice to uniquely determine 
the original embedding (up to scaling) and question why the energy approach is needed at all. This is because computing the original embedding requires solving a PDE with boundary conditions 
derived from the edges, and small (inevitable)
errors in detecting the boundary may lead to the PDE yielding no solutions or infinitely many solutions. In simple terms, while an exact computation is possible, this approach is unfriendly towards real world errors. 
The mathematically inclined reader may read more about why the energy functional is a good approach to the problem
in section \ref{sec.isgood}. \\

To this end we define the geodesic energy as $E \from C^\infty(Q) \to \R$ defined by
$\rho \mapsto \sum_\gamma E_\gamma[\rho]$. Note that we can safely assume that $\rho$ is smooth since $S$ needs to be smooth. 
Although we would like $E[\rho] = 0$, this is unachievable in practice. Therefore, the core method used to recover $S$ will be to minimize $E[\rho]$. Gradient descent is therefore apt. \\

The rest of the section will focus on computing the energy more explicitly, and consequently we assume some familiarity with differential geometry. For readers more experienced in differential geometry, the tangential 
acceleration that we want to compute is exactly the geodesic curvature $\kappa_g$ of $\gamma_\rho$, and this is explicitly given by
\[
  \kappa_g = \frac{(N \times \dot\gamma_\rho)\cdot \ddot\gamma_\rho}{\abs{\dot \gamma_\rho}^3}
\]
Since the implementation uses curves that do not necessarily have uniform speed, squaring and integrating (after a change of variables) directly gives us an explicit expression for the energy:

\[
  E_\gamma[\rho] = \int_0^T \abs{[\ddot \gamma_\rho(t)]^T}^2 dt = \int_0^1\frac{\abs{N(\gamma_\rho(s)) \cdot (\dot \gamma_\rho(s)\times \ddot \gamma_\rho(s))}^2}{\abs{\dot\gamma(s)}^5}ds
\]
The normal can be computed using $\rho$ itself as the parametrization and all derivatives are easily evaluated using the chain rule. The details are explained below. \\

We will assume that we may compute the derivatives of $\rho$ and the derivatives of $\gamma$. We have already seen that we can accurately compute
the derivatives of $\gamma$ with respect to $t$, and computing the derivatives of $\rho$ with respect to $x$ and $y$ can be done similarly --- more on this later. We may then use the chain rule to compute $\rho'(t)$ 
and $\rho''(t)$ which then directly gives us $\ddot \gamma_\rho(t)$. 
We are only left to compute $\ddot \gamma(t)^T = X(p)^T$, where $p = \gamma_\rho(t)$, and refactor speed into the equations. \\~\\
Fix a point $p \in S_\rho$ and suppose that $X$ is a vector in $\R^3$ with basepoint $p$. The vector $X$ decomposes as $X = X^T + (X\cdot N) N$ where $N$ is the normal vector at $p$. So we need to compute the normal $N(p)$
of $S_\rho$. This can be done using standard differential geometry. To do so, we construct a parametrization for $S_\rho$ around $p$ defined by $\varphi(x, y) \defeq \rho(x, y, f) (x, y, f) \in S_\rho$.
Note that when $p = \gamma_\rho(t)$, $(x_0, y_0, f) = \gamma(t)$. 
The tangent plane $T_p S_\rho$ 
is thus given by $\spann\{\del_x \varphi (p), \del_y \varphi(p)\}$. The normal $N(\gamma_\rho(t))$ is therefore
\[
  N(\gamma_\rho(t)) = \frac{\del_x \varphi(x_0, y_0) \times \del_y \varphi(x_0, y_0)}{\norm{\del_x \varphi(x_0, y_0) \times \del_y \varphi(x_0, y_0)}}
\]
where $(x_0, y_0, f) = \gamma(t)$. It is clear that
\[
  \del_x \varphi(x_0, y_0) = (\del_x \rho(x_0, y_0) x_0 + \rho(x_0, y_0), \del_x \rho(x_0, y_0) y_0, \del_x \rho(x_0, y_0)f)
\]
using the product rule. 
Now, since the speed is not necessarily constant, we will have
to take a further cross product with the velocity vector $\dot \gamma_\rho(t)$ to ensure that any nonzero tangential acceleration remains strictly along the direction of the curve (speeding up or slowing down only).
Taking this into account, we in fact have $\ddot \gamma_\rho(t)^T = N(\gamma_\rho(t)) \cdot (\dot \gamma_\rho(t)\times \ddot \gamma_\rho(t))$. The rest of the calculations will depend on $\rho$ and $\gamma$ specifically, 
and is detailed in the \verb|evaluate_penalties| method of \verb|detector/energy.py|. \\~\\
Finally, since in practice $\gamma(s)$ is defined in terms of an arbitrary parameter $s$ (ranging from $0$ to $1$ in our case),
rather than its arclength (which will be denoted $dt$ as before), we need to make the change of variables $dt = \abs {\dot \gamma_\rho(t)}ds$,
we have 
\[
  E_\gamma[\rho] = \int_0^T \abs{[\ddot \gamma_\rho(t)]^T}^2 dt = \int_0^1\frac{\abs{N(\gamma_\rho(s)) \cdot (\dot \gamma_\rho(s)\times \ddot \gamma_\rho(s))}^2}{\abs{\dot\gamma(s)}^5}ds
\]
This is because differentiating $\gamma_\rho(s)$ with respect to $s$ each time introduces a factor of $1/\abs{\dot \gamma_\rho(s)}$ exactly once. We are differentiating three times in the numerator and squaring
which gives a factor of $\abs{\dot \gamma_\rho(s)}^{-6}$ and we finally multiply by $\abs{\dot \gamma_\rho(s)}$ due to change of variables to obtain a factor $\abs{\dot \gamma(s)}^{-5}$. \\~\\
Other than the core geodesic energy computed above, the method \verb|evaluate_penalties| consists of many other penalties, which have currently been set to $0$, such as a penalty for high mean and Gaussian curvatures, 
a penalty on high arclength variance of geodesics and so on. The results can be fine tuned using these parameters, although we will stick to the geodesic energy for the most part.

\section{Gradient Descent}
The final part of the algorithm is to use gradient descent to find a minimizer $\rho$ for $E$. Typically, gradient descent is used to minimize functions $f \from \R^N \to \R$ over finite dimensional spaces. We however
have a functional over $C^\infty(Q)$. The simplest fix is to approximate. We sample the domain $Q$ across a uniform and discrete collection of points $D = \{(u_i, v_i)\colon i = 1, 2, \dots, N\}$.
The function $\rho$ is thus represented by a finite tuple $\vect x \in \R^N$ where $x_i = \rho(u_i, v_i)$. Therefore $E \from \R^N \to \R$. \\~\\
The gradient descent algorithm proceeds as follows:
\begin{itemize}
  \item We first start with an initial tuple $\vect x_0 = (1, 1, \dots, 1)$. This is the discrete representation of the function $\rho(x, y, f) = 1 \forall (x, y, f) \in Q$.
  \item We fit a smooth surface (a function of $u$ and $v$) to the collection of points $(u_i, v_i, x_i)$ using a global quadratic function of $u$ and $v$. This method additionally returns the derivatives of the surface
    $\rho_u$, $\rho_v$, $\rho_{uv}$, $\rho_{uu}$ and $\rho_{vv}$. To achieve this, we use the method described in section \ref{sec.fit} with a large enough \verb|bin_size| to obtain a global fit. See section \ref{sec.lim}
    for why a global fit is used instead of bump functions.
  \item We iterate through the detected curves and compute $E_\gamma[\rho]$ using the surface fit $\rho$ and its derivatives.
  \item The total energy is simply the sum of these energies obtained. We use autodifferentiation to compute $\grad E(\vect x)$.
\end{itemize}
We elaborate on the last step. Backwards autodifferentiation allows us to compute the derivatives of any function defined algorithmically. In our case, the input is $\vect x$ and our function $E(\vect x)$ involves
not just performing the integration but also fitting the surface to $\rho$ to $\vect x$. In our implementation, we used PyTorch to perform autodifferentiation. Finally we use the usual
gradient descent algorithm
$\vect x_{n+1} = \vect x_n - \eta_n\grad E(\vect x_n)$ to find a function $\rho$ (approximated by $\vect x_{n+1}$) that better minimizes the energy (as compared to $\vect x_n$). The iteration is stopped after
a fixed number of steps is completed, or is stopped early if the gradient falls below $0.5$ (this is set in \verb|test_gd.py| and the cutoff can be changed). \\~\\
In particular, the last method is known as Vanilla gradient descent. This is implemented in \verb|detector/gradient_descent.py| by the method \verb|run_vanilla_descent|. While this shows good results, another 
form of gradient descent used interchangeably in the project is gradient descent with momentum. This is implemented by \verb|run_adam_descent| using PyTorch's Adam descent method. 
This method includes a momentum term to speed up convergence. \\

\section{Why Energy is a Good Metric}\label{sec.isgood}
A natural question that may come up is why computing the energy is necessary in the case of a piece of paper which has zero Gaussian curvature everywhere. Indeed, if we assume that the paper is 
developable (has 0 Gaussian curvature everywhere) and is bounded by geodesics (for example
if the paper is a rectangle or any other polygon), the problem is trivial. Any disturbance on the paper necessarily propagates to at least one boundary since the Gaussian curvature is $0$. We can thus use just information 
from the boundary to uniquely construct the surface, leaving nothing to chance. Note that `unique' in this context refers to uniqueness up to globally scaling the whole surface (homothety). We will use `unique' to 
describe uniqueness up to scaling throughout this section. \\~\\
On the other hand, in the case when the boundary is not formed by geodesics, it is impossible to determine the full shape of the paper given finitely many geodesics. This is because in this case there ``outermost'' geodesics
and no information related to curvature is known outside of these. We will thus need a dense collection of horizontal geodesics and a dense collection of vertical geodesics to uniquely determine the original surface $S$.\\~\\
The same holds generally even when $S$ is not developable, i.e. a dense collection of geodesics along both directions is necessary and sufficient to uniquely determine the surface in general. \\~\\
If $K = 0$ eveywhere, we in fact have a PDE that describes $\rho$ (and hence the surface).
If the boundary of the paper is known to be made of geodesics, we will obtain a unique solution for this PDE upon imposing the boundary conditions. The PDE can be explicitly derived using Cartan's equations using the condition
$K = 0$, but we omit it.\\~\\
Thus, in the case where we have a rectangular piece of paper, the problem is uniquely solved by the above PDE upon establishing the boundary conditions that the boundary is made of geodesics. However, PDEs are highly sensitive to 
small changes and slight errors in computation can lead to an invalid result. The energy minimizing approach is thus more stable and accurate subject to real world error. It also generalizes easily to non-developable surfaces
with generic boundary given enough rulings. In particular, the energy functional $E[\rho] = \sum_\gamma E_\gamma[\rho]$ is an approximation of the function
\[
  E = \int_{G_{\text{vert}} \cup G_{\text{hor}}}\int_0^{T} \abs{\ddot \gamma_\rho(t)^T}^2 dt d\gamma_\rho
\]
where $G$ denotes the collection of geodesics (with subscript specifying direction). If minimized to $0$, this functional will uniquely reproduce the original surface.

\section{Limitations}\label{sec.lim}
In this section, we list some known limitations of the current implementation along with specific algorithms that may resolve these issues. \\~\\
The first limitation relates to the fact that we approximate $\rho$ with a discrete set of points $\vect x_0$. We can choose $N$ large enough that $\vect x_0$ provides a good approximation for $\rho$. However, when we
compute the gradient $\grad E(\vect x_0)$, this yields a completely different list of points $\vect x_1$. There is no mathematical guarantee that $\vect x_1$ approximates a smooth function and when $(u_i, v_i, x_i)$ is plotted
using values from $\vect x_1$, we could have arbitrary jumps and discontinuities. This is precisely the reason we use global quadratic fits in our gradient descent rather than using bump functions as described in 
section \ref{sec.fit}. When bump functions and local quadratic fits are used to fit a discrete collection of points that has arbitrary discontinuities, we will end up with a bumpy function that is far from 
the true direction of quickest descent. Successive iterations worsen accuracy and lead to the program producing an arbitrary surface as output. \\~\\
In our implementation, the code contains both methods. The \verb|surface_fit| function attempts to fit a surface using bump functions, but reverts to a global quadratic fit if too few points are found in every locality (bin). 
By setting the \verb|bin_size| to either a low value or a high value, we may force the function to return a global quadratic fit, which works better for our purpose. Passing a high enough \verb|bin_size| will lead to 
a single global bin so that the fit is global and passing a low enough $\verb|bin_size|$ leads to the method falling back onto a global fit due to a lack of data points in every bin. 
Despite this, a global quadratic fit may be inaccurate, since
this provides a rather crude approximation for $\vect x_1$. \\~\\
A possible way to overcome this inaccuracy is to apply a Gaussian blur filter on the collection $\{(u_i, v_i, x_i)\}$ where $\vect x_1 = (x_i)$ and follow this up with a more rigorous surface fit such as using bump functions. 
One can expect this to work better, although this has not been tested. The problem of inaccuracy is reduced but still persists with this method. \\~\\
The better method would be to get rid of approximations using finite dimensional vectors all together and proceed using mathematical methods related to gradient descent on Sobolev spaces. We outline this method below. \\~\\
Rather than approximate $\rho$ by a vector, we would like to directly perform gradient descent on $E$ as a function acting on $C^\infty(Q)$. We need to compute the gradient $\grad E(\rho)$ at any given $\rho$. We make
the notion of gradient precise. In particular, we must define the gradient in a way that $\grad E(\rho)$ is a $C^k$ function which captures information about $DE_\rho$, which is the usual Fr\'echet derivative.
The most natural way to do so is to 
choose a Hilbert space $\cal H$ and define $\grad E(\rho)$ to be the function in $\cal H$ such that $\gen{\grad E(\rho), h}_{\cal H} = DE_\rho (h)$ for all $h \in \cal D$. If $\cal H$ is a Hilbert space, the Riesz representation
theorem applies and a function satisfying this is guaranteed to exist. \\

For instance, if we choose $\cal H = L^2(Q^\circ)$,  then the gradient is $f \in L^2$, where $\gen{f, h}_{L^2} = DE_\rho h$. 
But once again, this only guarantees that the gradient is in $L^2$, which could be far
from smooth. So we instead use the Sobolev space $\cal H = H^m = W^{m, 2}(Q^\circ)$, which we know embeds into $C^k$ when $m-n/2 > k$. Moreover, this choice is valid since $H^m$ is a Hilbert space.
We thus perform gradient descent via the iterative algorithm
$\rho_{n+1} = \rho_n - \eta_n f_n$ where $f_n \in H^m$ such that $\gen{f_n, h}_{H^m} = DE_{\rho_n}(h)$ for all $h \in C^\infty(Q)$. 
This method has not been implemented yet, but seems like it would be apt for our case. \\

The next goal is thus to implement this fix. Further, the boundaries of the paper are currently not detected well. I aim to fix this issue and finally use this information to unroll the paper into a flat sheet and return 
its relative dimensions.
